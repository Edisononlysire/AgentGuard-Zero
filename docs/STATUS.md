### 2.1 最新本地源码与 CPU 反例核验

以下单独核验固定在公开源码 `1a4d45e9fd7e165331ef3f5c1e42e0c7cfd6d075`，直接调用当前编码函数；不是新增服务器模型推理。

| 检查 | 结论与证据级别 |
|---|---|
| 九条 evidence，同时有 event ID 和 evidence ID，候选引用最旧的 V0 | 实际 `_compact_public_state` 只保留 V1-V8，V0 丢失；确定性最小反例 |
| 最小输入只改变 `root_source_ids` | 实际 `public_state_text` 相同；来源依赖未充分表达的编码碰撞 |
| 最小输入只改变 `available_at` | 实际 `public_state_text` 相同；紧凑文本遗漏该时间差异 |
| `_apply_lifecycle_supervision` | 源码确认主标签先指定流程动作族，再族内选 Teacher-Q；其他 teacher 辅助信息仍有保留 |
| 历史中已有 authorized mitigation | 源码确认候选合法性会禁止后续缓解，不检查是否已充分缓解 |
| 动作族硬门控 | 源码确认先选族再族内排序；尚无历史 regret 归因统计 |

前三项证明条件成立时存在信息丢失，不证明它们出现于多少历史轨迹；来源信息也可能通过其他公开状态间接体现。上述问题尚未修复。增加输入信息可能影响 token 长度，必须重新检查长度上限和显存，不能声称开销必然为零。

另独立复算了老师的数学例子：在两世界各采一次完全无信息硬币并错误按样本结果分组时，样本内分类估值可为 75%，真实最优为 50%。这是随机教师的风险案例，不是当前旧版教师或模型分数已虚高 25 个百分点的实测结论。简化二状态的净 VoI +0.25/-0.15 也复算一致，不代表干预式工具可忽略世界转移。

## 3. 正式新实验前需要处理

| 问题 | 证据与处理 |
|---|---|
| 关键证据输入 | 修复多 ID 引用保留，补来源依赖与时间表示，并使动作族/候选视图拥有充分公共信息；保留超长显式失败。 |
| 流程要求暗示 | 输入、场景门控、标签覆盖与采样必须共同修正答案性流程暗示；真实预算、权限和证据前提继续公开。 |
| 公共教师 | 首版有界有限状态/信念搜索，正确观测似然与失败成本；不能从单次随机结果预知世界，也不能用流程族替代价值主标签。 |
| 行动效果与 belief 耦合 | 同一 LimitSession、同一目标，仅改变声明意图，缓解效果就不同。物理效果与意图识别应分开。 |
| Betrayal 指标宽松 | 公开信息“质疑所有声明”策略，在最小背叛场景中无工具即可获得检测率 1.0；合法变化也被质疑但旧误报指标为 0。应绑定来源、证据、时间及正常变化误报。 |
| Probe Yield 不是因果收益 | 当前检查后续证据引用，已不是任意工具调用计分，但不能代替有/无试探的净效用比较；确认原判断也可能有价值。 |
| 基线后处理 | 共享旧评测助手仍会改写朴素 Memory/Trust 策略。公平基线应保留自主拒绝；不能将朴素策略代表所有记忆智能体。 |
| 兼容入口 fallback | 旧 Level-1 助手缺失场景时仍可能回退。新正式入口应拒绝缺失协议与场景；不能依赖兼容默认值。 |
| 机制外泛化 | 哈希隔离不等于模板、机制或组合隔离；旧 retention 集不再是新协议最终测试。 |
| 门控与后续处置限制 | 先量化候选/门控/排序损失与处置链失败，确定任务允许行为后再决定修改，不立即全面重构。 |
